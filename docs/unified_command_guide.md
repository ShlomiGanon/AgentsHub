# מדריך הפעלה וארכיטקטורה: חמ''ל מבצעי אחוד (Unified Command Hub)

מסמך זה מרכז את כלל המידע המבצעי, הטכנולוגי ושלבי ההפעלה של הפרופיל המבצעי האחוד (**`profiles.unified_test`**), מערך הרשאות המשתמשים ב-Dashboard, לחצני הטלגרם לפי תפקיד, ניהול צי הרחפנים והמענה המבצעי הקצר בעברית.

---

## 1. מדריך הפעלה מהיר (Quickstart)

כדי להפעיל את המערכת בצורה תקינה בסביבת Windows PowerShell, יש לפעול לפי השלבים הבאים בסדר המצוין.

### שלב 0: טעינת משתני הסביבה (חובה בכל טרמינל חדש!)
אם מנסים להפעיל את השרת מבלי לטעון את קובץ הסביבה `.env`, תתקבל השגיאה:
```
failed to start API: required environment variable 'CORE_MODEL_PROVIDER' is not set
```
**הפתרון:** בכל חלון PowerShell חדש שנפתח, יש להריץ תחילה:
```powershell
.\load-env.ps1
```
הסקריפט יטען את כל 16 משתני הסביבה הדרושים (מפתחות מודל, BOT_TOKEN, הגדרות הצפנה ופורטים).

---

### שלב 1: הפעלת שרת ה-API וה-Dashboard
בחלון הטרמינל הראשון (לאחר הרצת `.\load-env.ps1`):
```powershell
python -m api.app profiles.unified_test
```
- **פורט השרת המבודד:** השרת רץ על פורט **`8905`** (מבודד מכל שאר הפרופילים במערכת).
- **מסדי נתונים מבודדים:** נוצרים אוטומטית בתיקייה `data/unified_test/`:
  - `data/unified_test/unified_surveillance.db` (מצלמות, רחפנים ומשימות)
  - `data/unified_test/unified_team_status.db` (מצבת כיתת כוננות ונוכחות)
  - `data/unified_test/unified_history.db` (יומן אירועים היסטורי)

---

### שלב 2: ניהול ואישור משתמשי טלגרם ב-Dashboard
**חשוב:** מנגנון המשתמשים הקיים והדשבורד הם **מקור האמת היחיד להרשאות**. משתמש שאינו מאושר ב-Dashboard ייחסם מיד בטלגרם ולא יגיע לסוכנים או ל-LLM כלל.

1. פתח דפדפן וגש לכתובת:
   ```
   http://localhost:8905/admin
   ```
2. הזן את פרטי ההתחברות לממשק הניהול.
3. הוסף או אשר את המשתמש לפי מזהה הטלגרם המספרי שלו (**`Telegram User ID`**):
   - בחר תפקיד **`COMMANDER`** (מפקד) — גישה מלאה לכלל הפעולות, שיגור והחזרת רחפנים, הזנקת כוחות ואישורי פעולה.
   - בחר תפקיד **`VIEWER`** (צופה / לוחם כוננות) — פעולות דיווח נוכחות אישי וצפייה בתמונת מצב בלבד.

> **חלופה ב-CLI (ללא דפדפן):**
> ניתן להוסיף משתמש ישירות משורת הפקודה:
> ```powershell
> python -m cli.user_admin --profile profiles.unified_test add --telegram-id <USER_ID> --level commander
> ```

### שלב 3: הפעלת בוט הטלגרם
בחלון טרמינל **שני נפרד** (גם בו יש להריץ קודם `.\load-env.ps1`):

### שלב 5 (אופציונלי): סימולטור תרחישים ב-Dashboard
ממשק הניהול (שפתו נקבעת לפי `DEFAULT_LANGUAGE` של הפרופיל — עברית ב-`unified_test`) כולל עמוד
**סימולטור תרחישים** בכתובת:
```
http://localhost:8905/admin/simulator
```
העמוד טוען קובץ JSON של תרחיש (בחירת קובץ, גרירה או הדבקה), מציג כרטיס לכל צ'אט או חיישן
שהתרחיש מגדיר, ומאפשר לשחרר את הצעדים אחד-אחד לפי הסדר. **כל צעד נשלח מהדפדפן ישירות ל-API
האמיתי** — `POST /Msg` להודעות ו-`POST /Event` לאירועי חיישן — עם `X-Identity` של השולח שהוגדר
בצעד, בדיוק כמו שהבוט שולח. לכן:

- `sender_identity` של כל צעד חייב להיות משתמש (או זהות חיישן) **רשום** ב-Dashboard; שולח לא רשום
  יקבל 401 מה-API (העמוד מזהיר על כך מראש).
- קבוצת טלגרם (`group`/`supergroup`) חייבת להיות רשומה בטבלת הקבוצות; הניתוב לתת-הסוכן נקבע לפי
  הרישום הזה, לא לפי התרחיש. קבוצה לא רשומה מסומנת באזהרה וה-API מסרב לה (403).
- התשובה המיידית (שאלה, שיחה, הבהרה) מוצגת בכרטיס; דיווח או בקשה שנכנסו לתור נעקבים דרך
  `GET /Job/<event_id>` עד לסטטוס סופי, כולל מצבי ביניים (ממתין לאישור מפקד, ממתין לפרטי אירוע).
- הכפתור "טען דוגמה" בונה תרחיש תקין מהמשתמשים והקבוצות הרשומים כרגע.

פורמט קובץ התרחיש:
```json
{
  "scenario": { "id": "SEC_001_PHASE_1", "title": "כותרת", "description": "תיאור", "tags": ["PHASE_1"] },
  "chats": [
    { "key": "response_team", "kind": "message", "label": "כיתת כוננות", "telegram_chat_id": "-1001234567890", "telegram_chat_type": "supergroup" },
    { "key": "commander_dm",  "kind": "message", "label": "רבש\"ץ", "telegram_chat_type": "private" },
    { "key": "fence_sensors", "kind": "event",   "label": "חיישני גדר" }
  ],
  "steps": [
    { "step": 1, "chat": "response_team", "sender_identity": "1002003", "sender_name": "אלי", "text": "בוקר טוב, אני במילואים עד שלישי.", "timestamp": "2026-09-06T07:30:00Z" },
    { "step": 2, "chat": "fence_sensors", "sender_identity": "sensor-north-1", "text": "smoke observed at gate 3" },
    { "step": 3, "chat": "commander_dm",  "sender_identity": "5551", "text": "תמונת מצב", "protocol_hint": "overall_situational_picture" }
  ]
}
```

- `chats[].kind`: `message` (ברירת מחדל) — נשלח ל-`POST /Msg`; `event` — נשלח ל-`POST /Event`.
- `telegram_chat_type`: `private` (ברירת מחדל), `group` או `supergroup`; לקבוצה חובה `telegram_chat_id`.
  שדות אלה מועברים ל-`/Msg` כמו שהם ומפעילים את ניתוב הקבוצות.
- `steps[]`: `step` מספר ייחודי שקובע את הסדר הגלובלי, `chat` מפתח של צ'אט, `sender_identity` ו-`text`
  חובה. אופציונלי: `sender_name` (תצוגה בלבד), `protocol_hint` (כמו לחצן מקלדת), `source_message_id`
  (אחרת נוצר מזהה ייחודי לכל ריצה, כדי שהרצה חוזרת לא תיחשב כפילות).
- `timestamp`, `title`, `description`, `tags`, `label` הם לתצוגה בלבד: זמן האירוע במערכת הוא תמיד זמן
  הקליטה בשרת, והסימולטור אינו מנסה לשנות זאת.

## 2. מקלדות ולחצנים לפי תפקיד (Role-Based Keyboards)

### מקלדת מפקד (`COMMANDER_KEYBOARD`)
מיועדת למשתמשים בעלי הרשאת `COMMANDER`:

| לחצן במקלדת | סוכן מטפל | פעולה / פרוטוקול | תיאור התוצאה |
| :--- | :--- | :--- | :--- |
| **📊 תמונת מצב כללית** | `surveillance_agent` + `team_status_agent` + יומן האירועים | `overall_situational_picture` | תמונת מצב הנבנית בזמן ריצה (Read-Only בלבד, 0 תופעות לוואי): הסוכן הראשי מנסח שאלה לכל תת-סוכן, תתי-הסוכנים עונים מנתוני הכלים העדכניים, נשלפים האירועים האחרונים מהיומן, והתשובה מנוסחת רק מהממצאים האלה. |
| **📹 מצב מצלמות** | `surveillance_agent` | `get_camera_feeds` | סטטוס עדכני של כל מצלמות האבטחה (פעילה, תקולה, זוויות תצפית). |
| **🛸 מצב צי רחפנים** | `surveillance_agent` | `get_drone_fleet_status` | מצב כלל הרחפנים: סוללות, כשירות, ורחפנים הנמצאים כרגע באוויר. |
| **🚀 הזנקת רחפן** | `surveillance_agent` | `dispatch_drone_to_incident` | מציג הנחיות לשיגור מהיר עם דוגמאות טקטיות (למשל: `'שגר רחפן לשער צפון'`). דורש אישור מפקד. |
| **🔄 החזרת רחפן לבסיס** | `surveillance_agent` | `return_drone_to_base` | החזרת רחפן ספציפי או כלל הרחפנים הפעילים לבסיס (דורש אישור מפקד). |
| **👥 סטטוס כיתת כוננות** | `team_status_agent` | `report_team_availability` | דוח מצבת נוכחות שמית מפורט: מי זמין, מי לא זמין ומי טרם דיווח. |
| **🚨 הזנקת כוחות** | `friendly_forces_agent` | `dispatch_emergency_forces` | הנחיות להזנקת משטרה, מד"א, כיבוי אש או צבא לפי גזרה (דורש אישור מפקד). |
| **📜 היסטוריית אירועים** | `history_agent` | `query_historical_incidents` | תחקור ושליפת 3–5 האירועים האחרונים מתוך יומן המבצעים. |

## 3. יכולות ניהול צי הרחפנים (`צי רחפנים`)

1. **סטטוס צי וסוללות (`get_drone_fleet_status`):**
   - סריקת כל הרחפנים במערך, חלוקה לרחפנים מוכנים (`ready`), באוויר (`in_flight`), בטעינה (`charging`) או בתחזוקה (`maintenance`).
   - חיווי אחוזי סוללה לכל רחפן.

2. **משימות פעילות באוויר (`get_active_missions`):**
   - הצגת כל המשימות האוויריות הפעילות בזמן אמת: מזהה משימה, אות קריאה של הרחפן, גזרת יעד, זמן הגעה משוער (ETA) ומטרת הסיור.

3. **שיגור טקטי מותאם גזרה (`dispatch_drone_to_area`):**
   - פקודה כמו: `"שגר רחפן לשער צפון"` או `"הזנק רחפן לגזרה דרומית לבדיקת חשד"`.
   - המערכת מאתרת אוטומטית את הרחפן הזמין בעל הסוללה הגבוהה ביותר, מחשבת זמן הגעה משוער (ETA) בשניות, ומעדכנת את הסטטוס ל-`in_flight`.
   - ברירת המחדל למטרת משימה: `"סיור ותצפית מבצעית"`.

4. **החזרה מבוקרת לבסיס (`return_drone_to_base`):**
   - תמיכה בהחזרת רחפן ספציפי (לפי אות קריאה או מזהה משימה) או החזרה גורפת (`"החזר את כל הרחפנים"`).
   - החזרת הרחפן לבסיס, סגירת המשימה ושינוי הסטטוס לקראת מוכנות לשיגור חוזר.

## 4. מנגנון האבטחה, ההרשאות ואישורי מפקד (RBAC & Approvals)

- **מניעת עקיפה דרך שפה חופשית:** אם משתמש בעל הרשאת `VIEWER` שולח בקשה לשיגור רחפן, הזנקת כוחות או החזרת רחפן, הבקשה נשמרת ומועברת לתור אישורי המפקד. שום כלי שינוי מצב אינו מופעל לפני שמפקד מאשר. אותה מדיניות חלה על טקסט חופשי, לחצן/`protocol_hint` ואירוע חיישן, ואינה תלויה בשפה או במילות מפתח שבהודעה.
- **חסימת משתמשים לא רשומים:** משתמש שלא אושר ב-Dashboard מקבל סירוב מידי עוד ברמת הבוט, מבלי להגיע לשרת הסוכנים.
- **מנגנון אישורי מפקד (Confirmation Holds):** פעולות בעלות השפעה מבצעית (שיגור רחפן, החזרת רחפן, הזנקת כוחות חירום) מחייבות אישור מפקד. המערכת עוצרת ומציגה בטלגרם כפתורי Inline: `[ אשר ]` ו-`[ דחייה ]`.
- **תמיכה באישורי טקסט (Text Approval):**
  - תמיכה במילות מפתח: `"אישור"`, `"אשר"`, `"מאשר"`, `"ביטול"`, `"דחה"`.
  - **בקשה פתוחה יחידה:** כאשר למפקד יש בקשת אישור אחת בלבד הממתינה להכרעה, שליחת הודעת טקסט מתאימה תפתור ותבצע את הפעולה מיד.
  - **מספר בקשות פתוחות במקביל:** אם קיימות מספר בקשות פתוחות, המערכת **אינה** בוחרת אוטומטית את האחרונה, אלא מנחה את המפקד להשתמש בכפתורי ה-Inline של הפעולה הרצויה כדי למנוע טעויות מבצעיות.
  - **עדיפות מבצעית:** כפתורי Inline נשארים מנגנון האישור המועדף והמאובטח ביותר.

## 5. ארכיטקטורת Multi-Agent Synthesis ומענה בעברית

- **זרימת מידע בתמונת מצב חיה (`orchestrator/situational_picture.py`):**
  ```
  Telegram Message ("📊 תמונת מצב כללית" / "מה תמונת המצב כרגע?")
        ↓
    MainAgent: תכנון - איזו שאלה לשאול כל תת-סוכן עכשיו, וכמה שעות אחורה לבדוק ביומן
        ↓
  [ SurveillanceAgent | TeamStatusAgent | יומן אירועים (history) ]   ← במקביל, כלי קריאה בלבד, נתונים חיים
        ↓
    MainAgent: ניסוח תמונת מצב אך ורק מהממצאים שהתקבלו כרגע
        ↓
  תשובה תמציתית בעברית + provenance (אילו תחומים ענו, מה נשאלו, חלון האירועים)
  ```
- **בזמן ריצה בלבד, ללא טקסט מוכן מראש:**
  - הסוכן הראשי אינו יודע דבר על המצב לפני הבקשה. הוא מנסח שאלה קונקרטית לכל תת-סוכן משתתף (רחפנים/מצלמות/משימות, מצבת כיתת הכוננות), ותתי-הסוכנים עונים מנתוני הכלים שלהם באותו רגע.
  - במקביל נשלפים האירועים האחרונים מיומן המבצעים לחלון הזמן שהסוכן הראשי בחר (ברירת מחדל 12 שעות, 1–72). לצופה נשלפים רק אירועים שהוא עצמו דיווח; למפקד - כולם.
  - התשובה מנוסחת רק מהממצאים האלה, עם המספרים והסטטוסים כפי שדווחו. תחום שלא ענה (שגיאה/פסק זמן) מסומן כ"לא התקבל דיווח" ואינו מושלם מהדמיון. אם המודל אינו זמין לניסוח, הממצאים עצמם מוחזרים תחת כותרת עם חותמת זמן.
  - שאלה חופשית המכילה "תמונת מצב" / "תמונת המצב" / "סטטוס גזרה" מנותבת ישירות למסלול הזה (ללא סיווג כוונה כללי), כל עוד הפרוטוקול קיים בהיקף הקבוצה.
- **אפס תופעות לוואי בתמונת מצב (`overall_situational_picture`):**
  - כלי התצפית (`get_surveillance_overview`) וכלי כיתת הכוננות (`get_team_status_roster`) מוגדרים כ-`side_effecting=False`; רק כלי קריאה מאושרים מועברים לתתי-הסוכנים.
  - לחיצה על "📊 תמונת מצב כללית" שולפת נתונים בלבד ואינה משנה בשום אופן את מצב כיתת הכוננות, מצב הרחפנים או המצלמות, ואינה יוצרת אירוע ביומן.
- **סינתזה מאוחדת ולא שרשור טכני:**
  - פלטי הסוכנים מוחזרים ל-Core Orchestrator, הממזג ומנסח תשובה אחת אחודה, תמציתית ומבצעית בעברית (עד 8 שורות).
  - הפלטים הגולמיים של הכלים (`steps_completed`) נשמרים ברישומי המערכת (Logging/Audit) לצורכי תחקור בלבד ואינם מוצגים כשרשור גולמי למפקד.
- **לכידת פלט ישירה (`ContextVar` + fallback) בפעולות סוכן יחיד:**
  - בפעולות פשוטות של סוכן יחיד (כגון שיגור רחפן, מצב מצלמות, סטטוס כיתה), הפלט העברי נלכד ישירות ומובא למפקד ללא עיבוד מיותר.
